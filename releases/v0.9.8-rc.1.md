# Shining Buddy v0.9.8-rc.1

本预览版修复本机工具被旧资源占用长期阻塞、最后只显示 `fetch failed` 的问题，并提供不依赖微信投递的本机工作台登录入口。

## 工具执行与恢复

- 新占用保存机器、开机和进程出生证明。有明确证据确认跨系统重启的本机旧占用可自动解除；原业务结果仍保留，不会重跑旧命令。远端执行、外部集成和证据不足的旧记录仍需核对。
- 不能自动恢复的旧占用立即说明阻塞来源与处理入口，不再让后续工具等到网络超时。仍在正常执行的任务继续按原顺序共享资源。
- 区分执行前预留、进入工具执行和执行后收尾。未开始的操作不遗留排他占用；工具已返回后，收尾连接或 Git 归属记录异常不会丢弃真实结果，也不会把它说成「尚未执行」。
- 「设置 → 执行与授权 → 执行方式 → 工具运行诊断」可查看占用及恢复记录。本人核对实际执行者停止后，可解除一条精确占用；版本变化或执行者仍存活时拒绝解除。
- 兼容早期没有资源占用记录的集成调用核对；跨库中断后可以按原身份完成核对，不重复执行集成调用。
- CLI 新增 `resources status` 与 `resources reconcile`，复用相同认证、版本与恢复契约。Worker 不持有本人恢复权限。
- 本机连接错误区分授权、资源协调与收尾阶段，提供操作是否已执行的边界；不直接把网络异常解释为 Worker 未启动。

## 工作台登录

- 从服务机器运行 `shining-buddy web open --data-dir /你的实例目录 --json --no-input`，获得一次性管理链接。由本机私有管理接口签发，短时、单次使用，换绑或重启后失效。
- 该入口不依赖微信登录确认的发送队列，微信处于发送冷却或投递故障时也可进入工作台。Vault 已锁定时仍需按页面提示解锁。
- 普通浏览器仍沿用微信批准；页面明确区分尚未发送、冷却和暂停，并提示本机恢复方式。

## 启动状态

- 修复同一启动代次的控制交接和身份发布窗口可能使实例概览短暂误报未就绪的问题。只在已有总等待时间内重读有证明的同代次状态，不跟随不同进程或代次，不重复停止操作。
- 管理页面可达与业务可用继续分开表示，不把维护或等待解锁显示成业务已启动。

## 升级

1. 备份原实例，停止旧服务并确认停止；有在途任务时先等待完成，明确需要取消时才使用 `service stop --cancel-active`。
2. 替换程序，以原 `--data-dir` 启动。保留 `config.toml`、项目、任务、Vault 和历史；仅替换文件不会更新正在运行的旧进程。
3. 用 `service status` 核对实际运行版本为 `0.9.8-rc.1`，再使用本机 `web open` 获取新入口。
4. 旧版没有开机证明的未知占用不会猜测解除；在工具运行诊断中核对后处理。解除占用只恢复后续执行，不能证明旧业务成功，也不自动重跑失败任务。

本次只扩展资源记录的可选证明与审计状态，不要求全实例搬迁或重写任务历史。已归档的恢复记录不属于活跃占用，早期版本不理解这些状态；回退前应停服并保留完整备份。

## 安装包与验证边界

提供 macOS ARM64 GUI/CLI、Linux ARM64/x64 CLI、Windows ARM64/x64 GUI/CLI，统一内置对应架构的 **kvault 0.5.0-rc.1**。macOS 使用 ad-hoc 签名，未做 Apple 公证；Linux 和 Windows 为交叉构建，不能视为目标系统原生运行验收。

发布门禁包含当前冻结源码的完整回归、真实 dsh、真实浏览器、SIGKILL 恢复、macOS 实包升级、构件摘要与官方发行签名回验。合成模型与隔离实例验证不替代真实用户模型表现、微信手机送达或目标机器长期运行。构建身份和各平台状态见 Release 附件。
