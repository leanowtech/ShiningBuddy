# Shining Buddy v0.9.3-rc.5

本版本为 **预发布候选（Pre-release）**，提供 macOS Apple Silicon 的 GUI ZIP 和单文件 CLI。

本次继续修复旧实例的启动与路径迁移兼容问题。部分实例已经迁移到 `config.toml`，但历史任务仍引用早期媒体、浏览器或自演进目录。旧程序可能继续查找已经退休的 JSON 配置，导致启动失败，日志显示 `portable_storage_preflight_failed:knowledge-run-locations / scan-error`。

## 修复与改善

### 旧目录引用兼容统一配置

- 历史 `media`、`browser`、`self-source`、`self-development`、`self-release` 目录引用从实例内统一配置的对应设置分区解析。
- 不再依赖已经退休的 `media.json`、`browser.json` 或 `self-improvement.json`。
- 统一配置中缺少必要目录时仍明确报错，不会从遗留 JSON 恢复陈旧配置，也不新增配置覆盖来源。

### 项目根缓存跟随配置更新

- `config.toml` 更新或被替换后，项目根缓存同步失效，避免继续使用旧目录关联。
- 保留项目归属、路径边界和缺失根校验，不通过猜测归属或扩大权限解决迁移问题。

### 保留已有历史位置索引

- 已迁移的知识任务继续校验现有位置索引，不从不可变的历史原文路径重新构造当前位置。
- 缺失或格式错误的位置索引仍需迁移或处理，不能直接跳过检查。
- 历史执行记录和原始回执保持不变，不做全文路径替换。

本版本同时包含 rc.4 的已有路径归属修复、控制库扫描去重和旧导入快照兼容处理；详见 [rc.4 发行说明](https://github.com/leanowtech/ShiningBuddy/blob/main/releases/v0.9.3-rc.4.md)。

## 升级步骤

1. 核对原实例的数据目录，等待活动任务结束后正常停止服务。仅关闭 GUI 窗口不会停止后台服务。
2. 备份原程序、实例数据目录和外部项目目录。运行期 socket 不作为普通备份文件归档。
3. GUI 用户完整解压新包，通过「打开已有助手」选择原实例；CLI 用户替换原程序后继续使用原 `--data-dir`。
4. 核对自启动登记的程序路径，避免仍启动旧程序。
5. 核对 `service status` 返回 `process: running`、`control: ready`，然后在 WebUI 使用原主密码解锁已有 vault。
6. 检查项目、会话、定时任务和凭据状态。此前结果未知的任务先核对执行记录，不直接重跑。

无需为本次更新删除历史任务、清空资产索引、恢复退休的 JSON 配置、重新绑定微信或重建 vault。

配置格式仍为 `3`、身份格式仍为 `2`、可移植路径格式仍为 `2`；内嵌 Node.js `24.18.0` 和 kvault `0.5.0-rc.1`，没有升级凭据库格式。从更早版本升级仍可能触发既有导入流程，不能跳过引导；回退时需核对数据格式兼容性，必要时恢复升级前备份。

## 验证情况

- 同一构建源码的 119 项实例兼容检查、8 项启动器契约检查、56 项凭据与恢复检查、38 项打包契约检查通过；另完成 23 项启动与路径定向回归。各组覆盖有重合，不将执行次数当作独立场景总数。
- 使用真实旧安装包和同一个隔离实例，重现历史目录引用导致的预检失败；换用 rc.5 后，实际程序成功启动，私有管理接口就绪，迁移完成并正常停止。
- 上述专项验证逐字节核对 3,075 份历史记录，包括 400 份已有位置索引，均保持不变。
- 实包的早期实例导入、已有实例直接升级两条路径通过，均保持业务暂停并进入受限设置状态。
- CLI 运行自检、TOML 配置检查、隔离服务检查、GUI 签名和内嵌 CLI 摘要一致性已核对。

工程验证仅使用隔离合成数据，没有访问真实业务实例、真实凭据、模型或微信账户。目标实例仍需在部署后完成启动与业务核验。

## 已知限制与构建来源

- GUI 使用 ad-hoc 签名，尚未完成 Apple 公证；本轮没有完整复验原生 GUI 的全部操作流程。
- 默认 Chrome 下的实包导航性能验收仍待完成；软件渲染功能回归不替代原生性能验收。
- 真实手机 Safari、软键盘交互、模型响应和微信送达不在本轮工程验收范围内。
- 本次程序来自隔离源码快照，以 `release-manifest.json` 中的 `source.sha256` 标识，不虚构源码 Git 提交。公开 Release 的 tag 指向公开文档提交，与程序构建来源分别记录。
- 公开仓库只用于文档和安装包分发，不接收核心开发源码 Git 历史；程序仍包含可提取的运行 JavaScript。
