# Shining Buddy v0.9.3-rc.3

本版本为 **预发布候选（Pre-release）**，提供 macOS Apple Silicon、Linux ARM64 / x64、Windows ARM64 / x64 安装包。

`rc.3` 主要完善安装包内容与 GitHub 发行流程，并补齐 Linux、Windows 构建；同时包含 `0.9.3` 系列此前已实施的启动稳定性、页面切换、产出物阅读和模型过载恢复改善。

## 本次新增与调整

### 发行包与源码边界

- 普通安装包移除核心开发源码快照、测试工程、第一方 TypeScript 类型声明和 source maps。
- Windows GUI 包不附带开发工程和调试符号文件。
- 保留正常运行所需的 JavaScript、Node / Python 凭据 SDK、框架文档、字体和第三方许可证。
- 普通包缺少核心开发工程时，不再将其当成服务启动失败；日常记忆、Skill、任务、指令和权限配置继续可用。
- 核心代码开发需要显式提供匹配的开发源码。本 Release 不提供核心开发工程；保留运行 JavaScript 不代表程序不可逆向。

### 全平台构建与发行

- 提供 5 个平台目标的单文件 CLI，以及 macOS、Windows 的 3 个 GUI ZIP，共 8 个程序附件。
- GUI 内嵌 CLI 与对应独立 CLI 的摘要一致。
- 核对程序、内嵌 Node、kvault、原生依赖和 Windows helper 的目标架构及对应摘要。
- 公开发行仓库与核心源码使用独立 Git 历史；GitHub 仓库用于产品文档、发行说明和安装包分发。
- 发布工具按明确白名单收集附件，检查版本、构建来源及摘要；上传只创建草稿，并执行下载回验，公开发布由维护者单独完成。

## 0.9.3 系列累计改善

以下改进来自此前的 `rc.1`、`rc.2`，已包含在本版本中。

### 启动与升级稳定性

- 补齐启动路径迁移、项目根解析和根绑定等数据库连接的短时锁等待，减少数据库短暂占用导致的启动失败。
- 保留等待上限与明确失败行为，不通过删除实例锁、结束未知进程或重跑业务任务解决冲突。
- 升级验收改用动态分配的端口，减少固定端口冲突对检查结果的干扰。

### 页面切换与刷新

- 有缓存的页面先呈现已有内容，再恢复连接并读取最新状态，减少切页时的等待。
- 减少重复的页面边界、滚动高度和聊天尺寸测量。
- 修复快速切页时旧响应覆盖当前结果，以及缓存页面再次进入时被加载状态忽略的问题。
- 保留会话草稿、阅读位置和浮层保护，延迟返回的旧请求不能覆盖当前页面状态。

### 产出物与文件阅读

- 统一任务、运行记录和成果中的只读文件阅读体验。
- 支持报告目录、阅读与源文切换、正文复制、CSV 网格、JSON 格式化、Word 段落阅读和 XLSX 工作表选择。
- 改善图片缩略图与缩放、HTML / PDF 预览、局部加载和错误重试；保留原文件下载及预览范围说明。
- 手机文件阅读时减少无关工具栏占用，改善标题区、表格横向滚动提示和完整成果入口。
- 文件切换及关闭时释放媒体资源，避免旧文件的延迟响应覆盖当前文件。

### 审批、设置与模型恢复

- 审批可在当前浮层逐项续办；任务文件在原阅读区域打开并保留返回位置。
- 继续讨论成果时携带经校验的引用，减少将长正文重复粘入对话。
- 模型设置中的低频字段逐步展开，后台刷新复用状态通知，减少对输入和焦点的干扰。
- 模型返回 `engine_overloaded` 时进入有限退避重试，只恢复失败的模型步骤，不整任务重跑，也不自动更换模型。
- 重试仍未恢复时提供中文说明，原始诊断留在排障记录中。

- 使用 GUI 时，下载对应 ZIP 并完整解压；GUI 已包含匹配的 CLI，无需另下独立 CLI。
- CLI 内嵌 Node 与对应平台的 kvault，无需另装 Node.js。Windows GUI 自包含 .NET 运行组件，无需安装 .NET SDK。
- Linux 包面向 glibc 系统，Alpine 等 musl 系统不在当前构建目标内。安全增强模式的 service 会话依赖 Linux 5.3+ 的 pidfd 支持和足够的锁页配额。
- 本次沿用各平台已经锁定的 kvault 版本，没有将 Linux、Windows 的依赖统一升级到 `0.5.0`。

## 升级说明

1. 核对当前实例使用的数据目录，等待活动任务结束后正常停止服务。仅关闭 GUI 窗口不等于停止后台服务。
2. 备份原程序、实例数据目录和外部项目目录。运行期 socket 不作为普通备份文件归档。
3. 替换程序。GUI 用户完整解压新包，通过“打开已有助手”选择原实例；CLI 用户继续使用原 `--data-dir`。
4. 核对系统自启动登记的程序路径，避免更新后仍启动旧程序。
5. 打开 WebUI，按提示完成版本检查或原有迁移流程；已有 vault 使用原主密码解锁。
6. 核对运行版本、项目、会话、定时任务与凭据状态。任务执行结果和通知送达分别检查。

本次不推进实例格式：配置格式仍为 `3`、身份格式仍为 `2`、可移植路径格式仍为 `2`。无需因本次更新清空实例、重新绑定微信或重建 vault。

从 `0.4.x` 等早期版本升级时，仍可能触发既有的实例导入和格式迁移流程，应按引导完成；不能将本次“格式不推进”理解为早期版本只覆盖程序即可跳过迁移。

需要回退时，应同时核对旧程序与数据格式的兼容性；必要时恢复升级前备份，不只替换旧程序。结果未知的业务任务不要直接重跑。

- 跨平台补包的 38 项打包检查、Windows 启动器 16 项契约断言通过。
- 从四个最终 Linux / Windows 单文件程序提取内嵌归档并复检；两个 Windows GUI ZIP 实际解包、架构及内嵌 CLI 一致性检查通过。

工程验证使用隔离合成数据，不访问真实业务实例、真实凭据或生产服务。

### 尚未完成与已知限制

- **Linux、Windows 目前完成交叉构建与静态检查，尚未完成目标系统实机运行验收。** manifest 保留相应的 `runtimeValidated=false`、`serviceValidated=false`。
- macOS GUI 使用 ad-hoc 签名，尚未完成 Apple 公证；Windows 包未做 Authenticode 签名。
- 默认 Chrome 下的实包导航性能验收仍待完成；此前长文就绪阶段出现超时，软件渲染功能回归不能替代这项原生性能验收。
- 真实手机 Safari、软键盘交互，以及真实模型和微信送达不在本次工程验收范围内。

因此，本版本保持 **Pre-release** 标记，不作为全平台正式验收版本。

macOS：

```sh
shasum -a 256 Shining-Buddy-v0.9.3-rc.3-macos-arm64.zip
```

Linux x64：

```sh
sha256sum shining-buddy-v0.9.3-rc.3-linux-x64
```

```powershell
Get-FileHash .\Shining-Buddy-v0.9.3-rc.3-windows-x64.zip -Algorithm SHA256
```
