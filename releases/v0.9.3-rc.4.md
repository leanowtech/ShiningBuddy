# Shining Buddy v0.9.3-rc.4

本版本为 **预发布候选（Pre-release）**，提供 macOS Apple Silicon 的 GUI ZIP 和单文件 CLI。

本次重点修复旧实例升级后服务无法启动的问题。部分实例在升级时会持续占用 CPU，最终提示 `Service startup timed out`；日志中可见 `portable_storage_preflight_failed` 和 `ambiguous-root`。新版修复了路径归属误判及重复扫描，并补齐旧迁移记录的兼容处理。

## 修复内容

- 已有资产工作区的 `sb-path:v1:` 引用保留其声明的项目或外部根，按引用直接校验，不解码成绝对路径后重新猜测归属。修复已有项目 ID 的记录被误判为 `ambiguous-root`，导致服务启动退出的问题。
- 没有归属信息的绝对路径、非法引用与缺失根仍保留校验，修复不扩大访问权限或改变冻结审批动作。
- 已完成旧导入的实例在后续存储收尾时，按本次迁移前后核对业务数据，允许原导入结束后的合法增长；原始导入快照不改写，本次迁移中的业务变更仍拒绝放行。
- 一次存储预检只发现并分组控制库一次，避免每个库重复遍历全部 worker 目录；减少长时间使用实例升级时的重复扫描。
- 未完成的原始导入仍使用其原始基线核验。本次迁移期间发生的意外业务变更仍拒绝放行。
- 在 48 个控制库的隔离回归中，相关目录发现次数由 51 次降为 1 次。这是该用例的结果，不代表所有实例的启动耗时比例。

## 升级步骤

1. 核对原实例的数据目录。等待活动任务结束后正常停止服务；仅关闭 GUI 窗口不会停止后台服务。
2. 备份原程序、数据目录和外部项目目录。运行期 socket 不作为普通备份文件归档。
3. GUI 用户完整解压新包，通过「打开已有助手」选择原数据目录；CLI 用户替换原程序后继续使用原 `--data-dir`。
4. 核对自启动登记的程序路径，避免仍启动旧程序。
5. 启动后核对 `service status` 返回 `process: running`、`control: ready`。在 WebUI 使用原主密码解锁已有 vault，再核对项目、会话、定时任务和凭据状态。

本次无需删除资产索引、清空实例、重新绑定微信或重建 vault。此前启动失败也不意味着应该手动重跑业务任务；先核对其实际执行结果。

配置格式仍为 `3`、身份格式仍为 `2`、可移植路径格式仍为 `2`。macOS ARM64 继续内嵌 Node.js `24.18.0` 和 kvault `0.5.0-rc.1`，没有升级凭据库格式。

从 `0.4.x` 等早期版本升级，仍可能需要完成既有导入流程。需要回退时，应核对旧程序和数据格式是否兼容，必要时恢复升级前备份。

## 验证情况

- 20 项启动与路径定向回归、124 项实例兼容检查、56 项凭据与恢复检查、38 项打包契约检查通过，共 238 项；没有失败、取消或跳过。
- 使用实际历史安装包和同一个隔离合成实例，复现 `0.9.2-rc.1` 可启动、`0.9.3-rc.3` 因归属误判退出，再验证修复版本恢复启动与管理接口就绪。
- 核对 335 条带归属的资产路径保持不变，后来新增的项目保留，原始导入快照未改写。
- macOS 实包运行自检、TOML 配置检查、隔离服务启动与停止检查通过；GUI ZIP 完整性、签名和内嵌 CLI 一致性已核对。

上述工程验证使用隔离合成数据，没有访问真实业务实例、真实凭据、模型或微信账户。目标实例仍需在部署后完成启动与业务核验。

## 已知限制

- GUI 使用 ad-hoc 签名，未完成 Apple 公证。
- 默认 Chrome 下的实包导航性能验收仍待完成；软件渲染功能回归不替代这项原生性能验收。
- 真实手机 Safari、软键盘交互、模型响应和微信送达不在本次工程验收范围内。
- 本版本包含 `0.9.3` 系列此前的页面、文件阅读和模型过载恢复改善，累计说明见 [rc.3 发行说明](https://github.com/leanowtech/ShiningBuddy/blob/main/releases/v0.9.3-rc.3.md)。

## 校验与反馈

下载后校验所选文件，例如：

```sh
shasum -a 256 Shining-Buddy-v0.9.3-rc.4-macos-arm64.zip
```

将输出与 `SHA256SUMS` 中同名条目比较。只有下载齐清单中的全部文件时，才运行 `shasum -a 256 -c SHA256SUMS`。

公开仓库仅用于文档、发行说明和安装包分发，不包含核心开发源码。构建来自包含未提交变更的源码快照，基础提交、`dirty` 标记和源码 SHA-256 见 manifest；包内仍包含可提取的运行 JavaScript。

反馈时请提供版本、系统架构、GUI / CLI 使用方式、是否旧实例升级、复现步骤及脱敏错误。不要提交主密码、API Key、凭据文件或完整实例数据。
