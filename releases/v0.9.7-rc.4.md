# Shining Buddy v0.9.7-rc.4

本版改善 WebUI 的状态说明和操作路径，重点解决“等待模型并发名额”含义不清，以及读取失败时已经显示的成果或执行过程被清空的问题。

## 模型等待与并发设置

- 只有模型请求确实排队时才显示等待名额。取得名额后恢复准备状态，向模型服务发出请求后再显示等待响应。
- 未显式配置的全实例模型请求并发上限从 3 提高到 **6**。保留已经明确保存的设置及缺少来源证明的旧值，不擅自覆盖。
- 对话进度提供可展开的占用数量、共享范围和设置入口；入口直接展开并发字段，保留对话草稿和已展开的说明。
- 模型请求名额由普通对话、微信入口、定时任务和专家协作共享，当前仍跨模型服务计数；它与独立任务数、token 用量和任务总调用次数分开控制。
- 消息入口改用“准备这条消息”“确认任务安排”等自然说明，未提交的工作不显示成已经执行。

## 成果、审批与通知

- 分组任务及单次运行中，成果或执行过程读取失败时保留已显示正文、附件和步骤；技术信息可展开查看。
- 操作明确为“重新读取成果”“重新读取执行过程”等，不会重新运行任务。读取恢复后清除错误，即使成果正文没有变化也能恢复正常状态。
- 审批记录明确区分“已批准本次操作”“授权已使用”和任务执行结果，删除重复的助手说明，让手机上的批准和拒绝动作更易找到。
- 通知动作改为“不再提醒这条通知”，明确没有补发，实际发送状态保持不变。

## 页面与设置

- 任务普通视图提供“发起任务”，定时视图提供“新建计划”。空列表可前往对话或查看历史，不再要求选择不存在的任务。
- “工作方式”入口改为实际目标“专家与协作”；运行列表提示可查看运行记录。
- “浏览器访问”更名为“工作台登录”，按需读取真实登录状态，区分访问令牌和浏览器批准记录；退出或撤销不会清空凭据库。
- 版本维护先说明官方版本更新；专家空态统一动作名称与主次层级。

## 升级

保留原 data-dir，正常停止服务，替换程序并重新启动；需要时在 WebUI 解锁凭据。请用 `service status` 核对运行版本为 `0.9.7-rc.4`，仅替换 CLI 不会更新已经运行的旧进程。

本版不新增实例格式或配置来源；默认独立任务数仍为 3。运行中的任务保留原输入、模型和权限。读取失败不自动重跑业务，关闭提醒不改变发送结果，批准记录不代表执行成功。

五个平台继续内嵌 **kvault 0.5.0-rc.1**。提供 macOS arm64 GUI/CLI、Linux arm64/x64 CLI 和 Windows arm64/x64 GUI/CLI。macOS 使用 ad-hoc 签名，未做 Apple 公证；Linux/Windows 交叉构建不代表目标机器实机验收。

这是预发布版本。仅接收正式版的实例不会被强制切换到 RC；可在「设置 → 界面与系统 → 版本维护」选择接收预览版，或手动安装。
