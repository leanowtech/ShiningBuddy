# Shining Buddy v0.9.8-rc.3

本次为预发布版本，重点改善工具连接、模型断线恢复、通知补发、浏览器读取和日常后台开销。

## 主要变化

- 修复升级放行或服务排空后，顶层业务就绪状态仍沿用旧值的问题；状态查询跟随实时准入，打包升级验收覆盖凭据设置后的实际业务放行。

- 本机审批和工具控制增加同调用回执恢复。响应丢失时核对原回执，不再次请求批准、不重复删除文件；消费过的批准不能启动第二次业务操作，启动前重新核对权限版本。
- 工具事实区分“尚未执行”“已有结果”和“结果未知”。参数或文件前置条件拒绝不会误阻止续接；后台命令通过实际 producer 结束记录收敛原调用；具备 shell 的协作成员可收集自身后台结果，未知外部效果仍须核对。
- 统一模型网络错误分类。可恢复的断线只重试失败的模型步骤，保留已完成工具结果，继续使用用户所选模型；搜索仅在尚未向下游交付结果时有限重试。
- 通知详情显示真实前序阻塞、暂停、冷却和通知时间。可以预演并补发选中的已有内容，或取消真正尚未发送的部分；不重新生成成果，已接受内容不重发，可能重复的发送仍需本人确认。
- 通知组操作支持 WebUI、CLI 和对话中的管理工具。冲突保留选择和阅读位置；历史未解决故障不再仅因超过七天就消失，关闭提醒后仍保留发送事实。
- 浏览器只读抓取使用独立 Page 事务，不覆盖正在操作的表单；只对确定的只读导航失效做一次恢复，交互提交不自动重放。
- 项目根缓存避免未变化时反复打开 SQLite；成果扫描在空闲时退避，新成果完成或手动刷新会唤醒。
- 新增有时间、阶段、来源范围的安全诊断日志，以及本机拥有者使用的历史修正预演。缺少证据的旧记录保持待核对，不自动归档、释放资源或重跑。

继续保留 rc.2 的长任务时限、按版本延长在途预算和原检查点续接能力。dsh 固定为 0.2.1-rc.2；各目标内置 kvault 0.5.0-rc.1。

## 升级与数据

1. 使用同一实例的 `--data-dir` 查询状态。先排空任务后正常停止服务；需要取消在途执行时，明确使用 `service stop --cancel-active`，已执行操作不会撤销。
2. 备份实例和原程序，核对进程已退出后替换对应程序；不创建第二个 data-dir。
3. 使用同一 data-dir 启动，在 WebUI 按需输入原 Vault 主密码，核对运行版本、凭据及业务准入。

v2 控制表按实际启用的组件准备：既有工具库先备份、核验再激活；全新空库直接初始化。不会为本功能批量升级全部历史 Worker，也不扩展基础路径迁移清单。控制回执只存原账本引用，不复制机器绝对路径。

未知控制操作、仍活跃的补发链等状态会阻止不安全降级。不要清空回执或用整份旧实例覆盖新数据；需要回退时先停止服务，使用对应备份并核对兼容条件。

## 发行与验证边界

安装包不包含核心开发源码和第一方 source maps，运行所需 JavaScript、凭据 SDK、框架文档和第三方许可保留。macOS GUI 使用 ad-hoc 签名，未经 Apple 公证；Windows GUI 是交叉构建预览，未完成 Windows 原生运行验收。Linux/Windows 交叉构建与 macOS ARM64 原生验证分开记录。

发行物中的 `release-manifest.json`、`SHA256SUMS` 和官方签名用于核对构件身份。工程全量回归、真实 dsh、真实远程模型、性能对照及构件升级验证分别保留回执；这些不代表已经在每位用户的机器或微信手机上验证送达。本次发布不包含实例远程部署。
