# Shining Buddy v0.9.5

本版重点改善重度使用时的消息处理：可以连续派发多个任务，也可以在任务执行中追加要求。新请求由模型结合本轮上下文和实际任务状态判断归属，同项目与跨项目都能并行处理。

## 主要改进

- 默认同时处理 3 项任务，可在执行设置调整为 1–8 项。前台、定时执行与协作共享容量，超过容量的请求保留等待。
- 一条消息可同时补充现有任务和启动独立任务。已完成成果的修改保留原任务关系及版本，不把所有新消息机械地续到同一个会话。
- 已保存但尚未执行的要求也能追加修订，迟到决策不会覆盖后续纠正。新附件优先按本轮事实处理，不自动拿旧文件凑上下文。
- Web 任务卡片提供独立取消和“补充这项”；多任务时隐藏没有唯一目标的全局控制。刷新后保留草稿和阅读状态。
- 微信“全部停止”可以停止运行中及等待中的任务，保留定时计划和已经发生的执行事实。
- 在微信里批准浏览器登录时，核对验证码后回复“确认登录”。有多个申请时，复制对应通知里带核对码的命令。

## 可靠性与体验修复

- 查询与最终决策使用一致的工具交互，修复入口模型反复查询、没有提交新任务的问题。无效候选由模型结合原话修复一次，不生成固定任务菜单。
- 入口优先呈现本轮原话、附件、明确引用和最近可见对话。未关联的旧任务仍可按需查询。入口继承会话所选模型，裁减小窗口里的可回读预览。
- 独立且完整的请求可以原样转交业务助理，避免分派时把完整问题改窄。涉及多个分项或指代时，模型仍可给出对应范围。
- 新任务默认沿用来源项目；本轮指定多个项目时分别确定各项去处，避免选对动作却派错项目。
- 补清任务当前版本、执行代次与成果版本的工具含义；候选未执行时返回相关当前事实，避免模型因含糊报错反复改错目标。
- 明确引用旧成果时保留对应执行和版本，不替换为同任务的最新成果；普通追问只展示本轮可用的续接方式。入口只注入分派所需职责和工具。
- 区分用户仅收悉与用户要求执行，任务查询声明实际覆盖范围；不以口头应承代替任务提交，不把局部即时任务清单当成完整业务对象。
- 旧版本设置先并入实例 TOML，再进入启动和解锁流程，保留非默认配置及原备份。
- 协调同一文件、目录、symlink、浏览器及远程连接的冲突操作；读取后的文件被其他任务更新时，先重新检查，防止旧内容覆盖。
- 修复协作页异步渲染时操作按钮消失的问题；历史准备不再被较慢的协作历史请求阻塞。
- 确认原 Worker 已退出后，等待中的文件操作会重新核验并继续；不按超时抢占未知效果。
- 修复父任务、负责人及成员等待时耗尽 Worker 名额的问题；降低并发设置不会卡住已开始工作的子成员。
- 协作成员可在同项目独立写入，各成员的网页会话相互隔离，避免委派时争抢页面或全局忙碌状态。成员登录状态不自动共享。
- Git 暂存和提交核对变更来源，避免宽泛暂存混入其他任务尚未交付的内容。
- 补充按精确执行代次交付，区分已投递与已消费；未知消费或外部效果不自动重跑。
- 发送文件使用该次执行登记的成果副本。文件后来被改写不会串入另一任务；发送准备失败不会把已完成业务改记为失败。
- 改善历史消息向前读取时的排序、定位和刷新协调；通知记录按可处理问题呈现，减少无意义的常驻数量提醒。
- 启动迁移引导补充阶段、数据量及状态说明，区分管理可达、凭据待解锁与业务可用。修复启动期间管理端偶发读到尚未写完的实例身份。

- 修复新增模型服务和密钥时因其他服务的并行修改而产生的错误冲突；同一服务的并发修改继续受保护。首次绑定及中断后的恢复保留原凭据写入回执，避免重复写入。
- 修复双文件同名时交付版本核对失败，以及投递回执更新被误判为文件清单冲突。部分文件无法保存时保留正文和可用文件，并提示如何补齐。发送失败不会触发重新执行，也不会自动重复发送已确认的文件。

## 升级说明

1. 正常停止原实例并备份完整 `data-dir`；新程序继续使用同一个目录，不新建配置来源。
2. 首次启动会通过现有维护流程完成必要备份与格式升级。使用 CLI 提供的管理链接查看进展；不要将管理 ready 当成迁移已完成。
3. 如凭据处于锁定状态，在 WebUI 输入原主密码解锁。升级不要求在对话中提供密钥。
4. 实例身份与可迁移存储格式推进至 3；旧程序会拒绝写入新格式。回退请使用升级前完整备份及原程序，先核对升级后已经发生的外部效果。
5. 旧 Web 客户端仍可使用原 queue/steer 接口；刷新到新客户端后启用自动消息处理。

## 发行边界

安装包包含对应平台 kvault、运行时、框架文档与第三方许可，不包含核心开发源码或第一方 source maps。macOS GUI 为 ad-hoc 签名；Linux、Windows 的构建与实机验证范围以发行 manifest 和验证记录为准。平台接受发送不等于手机实际收到；真实账号与手机送达不使用合成测试冒充。
