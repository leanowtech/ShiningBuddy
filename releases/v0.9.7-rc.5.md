# Shining Buddy v0.9.7-rc.5

本版支持把定时任务的执行时间与结果通知时间分开：重量级工作可以在凌晨低谷时段执行，结果保存后，再在你指定的时间通知。

## 低谷执行，白天通知

- 默认交互保持简单：只设置执行时间，任务完成后立即发送符合通知策略的结果；旧任务行为保持不变。
- 在定时任务编辑器展开「更多设置」，选择「单独设置通知时间」。例如每天 02:00 执行、08:30 通知；支持每天、工作日和自定义 cron，共用任务时区。
- 结果提前完成后立即保存、释放执行资源，可以先在 WebUI 查看；不会占用任务名额等待通知。
- 错过通知时点时，默认等下一个通知时间，也可选择完成后立即补发。没有新结果时不发送占位消息。
- 修改通知设置只影响后续运行，已经排队、执行或等待发送的结果保留原设置。

## 通知可靠性与交互

- 「运行与结果」和通知记录分别显示执行完成与「等待通知时间」，并展示计划发送时刻。
- 延后发送的附件保留本次完成时的副本与内容摘要，避免项目文件后来被覆盖，发送成另一版。
- 服务重启沿用原通知时间和完成回执；恢复不重跑业务。附件副本遗失或被改动时，在发送前拒绝投递，保留已经确认的任务完成状态。
- 文件在本机不可读时，不再误报为可能已经发出的未知结果。
- 成功/失败是否通知仍由原通知策略决定；审批、凭据配置提醒和普通对话回复不受结果通知时间限制。
- 对话中的任务工具、WebUI 与 CLI 使用同一份通知配置。明确补发已有通知时立即安排发送，仍保留原有版本、拥有者和未知结果保护。

服务离线、凭据锁定或通道不可用可能使实际发送晚于计划。通知时点表示最早可发送时间，不保证手机准点收到。同一任务多次运行分别保存、分别通知，不自动合并结果。

## 权限设置页修复

较早的权限查询成功或失败时，不再覆盖后来出现的保存错误。通过浏览器返回触发保存失败后，错误说明与未保存的权限草稿保持可见，实际权限不变。相同错误再次到达时，不再重建提示卡；已展开的错误详情、焦点和浮层草稿会保留，不同错误仍正常更新。

## 升级与回退

保留原 data-dir，正常停止服务，替换程序后重新启动；需要时在 WebUI 解锁凭据。使用 `service status` 确认运行版本为 `0.9.7-rc.5`，仅替换 CLI 不会更新已经运行的旧进程。

本版不新增实例格式或配置来源，不会替已有任务自动开启延后通知。新配置只写入现有任务定义和通知队列。旧版程序不具备这项能力；若回退，应暂停已设置独立通知时间的任务并核对待发通知，避免新运行按旧行为立即发送。

提供 macOS arm64 GUI/CLI、Linux arm64/x64 CLI 和 Windows arm64/x64 GUI/CLI，五个平台内嵌 **kvault 0.5.0-rc.1**。macOS 使用 ad-hoc 签名，未做 Apple 公证；Linux/Windows 交叉构建不代表目标机器实机验收。功能回归使用隔离实例与脚本模型，不代替真实微信手机送达验证。

这是预发布版本。仅接收正式版的实例不会被强制切换到 RC；可在「设置 → 界面与系统 → 版本维护」选择接收预览版，或手动安装。
