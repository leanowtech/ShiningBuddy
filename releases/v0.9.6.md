# Shining Buddy v0.9.6

本版增加零模型调用的官方版本检测，并改善升级确认、运行版本识别和恢复；同时包含 0.9.6 RC 系列的消息响应与微信入口修复。

## 官方版本检测

- 存量实例手动升级并重启后自动启用，每天检查一次 GitHub 官方发行。无需创建定时任务、编辑配置或解锁 Vault，也不占用模型和业务 Worker。
- 支持手动检查、关闭自动检查、调整周期、选择正式版或预览版，以及忽略指定版本。重复升级保留已有设置和提醒记录。
- 使用语义化版本比较，正确处理 RC 数字顺序、RC 到正式版和平台匹配；不会把较旧的正式版当作当前 RC 的升级。
- 在「设置 → 界面与系统 → 版本维护」查看运行版本、最近检查、下一次检查、发行说明和匹配安装包。CLI 已替换但服务未切换时单独提示。
- 有适配新版时，通过已连接的消息通道提醒一次。离线或通道未就绪时延后，不发送每轮检查成功通知，也不增加普通任务数量。

## 确认后更新

- 有官方签名及兼容信息的后续发行，可下载到服务机器。先核对清单签名、平台、大小和摘要，再执行候选预检；旧清单继续提供手动下载。
- 查看具体计划并确认后，正常暂停新准入、等待当前任务结束、核算空间并备份，再切换程序。不会自动强杀任务或覆盖已有业务写入。
- 下载、备份、迁移、等待解锁和业务恢复分别显示。恢复操作沿用原升级记录，原来关闭自启动的实例不会被重新启用。
- 更新执行者与被替换服务分离。macOS 使用独立进程组；Linux 托管服务使用临时用户 systemd unit；Windows 使用当前登录用户的临时计划任务，不要求提供密码或提权。
- 首个包含此能力的版本仍需手动安装一次。发现新版不会自动停服安装；只有当前实例格式兼容且签名受信的包才开放应用内更新。

## 消息响应与可靠性

- 普通消息直接进入具备上下文和业务工具的完整助理，减少必经的独立分类调用；需要独立执行或跨项目时由模型选择派发。
- 微信派发成功入队后提供目标与状态回执，WebUI 显示真实等待阶段和耗时。
- 不可解析的旧收件记录不再阻塞后续消息；已有可靠完成证据时保留结果，避免仅因收尾退出状态丢失回复。
- 服务停止核验不再把语言或时区造成的启动时间显示差异当作进程已退出。

## 升级方式

五个平台的内嵌 kvault 统一为 **0.5.0-rc.1**，使用 KVAULT6 / IPC2。现有 KVAULT6 库沿用原密码和密文；Windows 等旧 KVAULT5 库在启动页面输入原密码后，按备份、副本迁移和逐条验证流程升级。迁移不会通过重新创建空 Vault 绕过原数据。

保留原实例 data-dir，正常停服、备份、替换程序并重新启动，不要清空项目、会话、任务或 Vault。仅替换 CLI 文件不会改变已运行的服务；请用 `service status` 核对运行版本、构建和业务准入，需要时通过 WebUI 输入原 Vault 密码。

自动检查设置保存在实例内 `config.toml`，默认不要求手工新增分区。检查状态、提醒回执和下载缓存均位于同一个 data-dir。公开安装包不包含核心开发源码或第一方 source maps。

## 平台与验证边界

macOS arm64 提供 GUI 和 CLI，Linux arm64/x64 提供 CLI，Windows arm64/x64 提供 GUI 和 CLI，均内嵌对应 kvault。macOS 使用 ad-hoc 签名，未做 Apple 公证。

发行验收包含类型检查、完整自动化测试、实例自包含与修复门禁、启动恢复、真实 dsh 审批链路、浏览器体验和安装包检查。Linux/Windows 构建不等同于目标机器的实机升级验证；真实微信手机送达、已有生产实例升级与各平台托管器仍需在对应部署环境观察。具体平台原生验证状态保留在发行清单中。
