# Shining Buddy v0.9.7-rc.2

本版修复微信多任务执行时缺少原生“正在输入中”提醒的问题，让用户能感知请求正在处理。

## 微信处理状态

- 附件准备、消息分派、助理与项目任务执行，以及微信请求发起的独立专家协作，共用当前微信绑定的输入状态，每 5 秒续期。
- 同时处理多项请求时，一项完成不会关闭其他在途任务的提醒；全部结束或取消后清除。取消、锁定、换绑和停服会终止旧状态。
- 输入状态接口暂不可用时独立恢复，不阻塞模型或正常回复，也不再将状态接口错误误报为消息投递失败。
- 保留各任务独立的执行、成果与通知记录，不增加模型分类步骤或新的业务路由规则。其他 Web 工作和普通后台定时任务不会占用当前微信的输入状态。

## 验证与发行改善

新增真实服务与双 Worker 回归，覆盖默认 5 秒续期、交错完成、接口故障和正常回复；补充迟到票据、取消与重启顺序、绑定代次和独立协作来源校验。

全量回归执行经过隔离审查的功能测试时，最多并发两个；性能与真实服务恢复仍独占，保留原有断言和真实超时等待。全量与专项在同一次完整执行中核验，减少重复测试。

## 升级

这是预发布修复版本。保留原 data-dir，正常停止服务、替换程序并重新启动；不要清空项目、任务、浏览器资料或 Vault。仅替换 CLI 不会更新已运行的服务，请用 `service status` 核对运行版本为 `0.9.7-rc.2`，需要时在 WebUI 解锁凭据。

五个平台继续内嵌 **kvault 0.5.0-rc.1**，沿用 v0.9.6 的签名更新清单。本版不增加实例格式迁移或新的配置来源，并包含 rc.1 的浏览器运行目录修复。

仅接收正式版的实例不会被强制切换到 RC；可在「设置 → 界面与系统 → 版本维护」选择接收预览版，或手动安装。

## 平台与验证边界

提供 macOS arm64 GUI/CLI、Linux arm64/x64 CLI，以及 Windows arm64/x64 GUI/CLI。macOS 使用 ad-hoc 签名，未做 Apple 公证；Linux/Windows 为交叉构建，不等于目标机器实机升级验收。

微信输入状态通过模拟 iLink 与真实 dsh Worker 验证，接口受理不等于手机一定显示；真实手机显示、用户模型语义和目标机器长期运行需要在对应实例验收。发行测试使用隔离合成数据。
