# Shining Buddy v0.9.8-rc.4

本次为预发布版本，修复微信通知持续被拒收、积压通知恢复不明确的问题，并补齐本机发送保护和明确的续接入口。

## 主要变化

- 为所有内置微信文字、图片、文件及控制通知统一记录实际发送次数。默认本地保护预算为 10 次，预留 2 次；这是本机保护策略，不代表微信官方额度或剩余额度，可在发送设置的高级选项中调整。
- 到期通知无法在保护预算内完整发送时，先暂存原通知，再由 Host 提醒一次。提醒会给出 `恢复通知 <6位码>`，无需模型判断，也不需要重新执行任务。
- 续接码绑定当前本人、微信绑定和本次暂存，有效期为 24 小时；旧码、引用、附件、复合输入和重复消息不会误放行。普通聊天仍可正常处理，不会自动批准发送积压通知。
- 小组通知先预留完整消息分项；超过预算的大组按原顺序分批发送。续接后的首个安全分项用于核验，实际获微信接受后才放行，避免反复要求确认却没有进展。
- 同一上下文出现 `prepare failed` 后停止新的提交，不再将其反复扩大为账号冷却。真正的 HTTP 429、Retry-After 和手动暂停仍然生效。
- 修复旧版实例导入时确认停服后页面可能停止检查的问题；后台仍在核验时继续读取真实进度，不要求重复停服。
- 保留已有明文凭据模式的收件与回复兼容性，复用原微信连接密钥生成作用域指纹；不自动启用 Vault，已启用 Vault 的实例不会降级。 不可读的历史上下文保留待核对，不再阻止接收和回复新的正常消息。
- 发送前重新核对当前绑定和上下文。重启、同一消息重复到达、乱序入站和旧响应回放不会重置预算或覆盖较新的故障；连续发送的多条正常消息仍能分别获得回复。
- WebUI 区分微信接收连接、首次缺少回复上下文、通知暂存、恢复核验、通知时点、平台冷却和发送结果未知；历史失败不冒充当前故障，旧等待记录按当前准入状态显示；提供复制续接指令及已有失败通知的核对入口。CLI 提供同等的本人管理操作，Agent 无法获取续接码或代替本人确认。
- 发送账本暂不可写时暂停后续发送，只补记原调用的已知结果，不重复发送。未知结果和旧失败记录继续保留，不会因输入续接码而被自动重发。
- 提供仅本人主动读取的加密发送诊断，限制响应体和错误样本大小；普通日志、Agent 状态及模型上下文不包含原始错误描述或控制码。

## 升级与使用

1. 沿用原实例的 `--data-dir`，先正常停止服务，核对进程退出后替换对应安装包或 CLI；不要新建另一份实例。
2. 启动后按需输入原 Vault 主密码。微信发送组件会先备份并校验 `tasks.sqlite`，再激活新增账本；本次组件升级不遍历备份全部历史 Worker 或缓存。
3. 如提示通知暂存，在微信连接设置中查看或生成续接指令，并在已绑定微信里单独发送完整指令。实际恢复仍遵守原通知时间、过期和组内顺序。
4. 已失败、已被接受和结果未知的旧发送不会因续接而重发。请在「运行与结果」核对通知组，需要时预演并选择要补发的已有内容；不必重跑业务任务。

旧版没有完整的上下文发送身份，升级后会明确标记记录覆盖范围。缺少证据时不推算官方余额；已有明确拒收证据会保守暂存。旧版未注明来源的账号冷却仍保留，不能靠换码或新消息清除真实限制。

存在活动暂存、恢复请求或预留时，不自动降级到不识别这些状态的旧版。回退程序与回退数据分别核对，不删除发送回执或迁移记录。dsh 保持 0.2.1-rc.2；各平台内置 kvault 保持 0.5.0-rc.1。

## 验证与平台边界

发行门禁包含完整工程回归、真实 dsh 控制入口、真实浏览器交互、组件备份和升级，以及真实进程 SIGKILL 与接收端已收到 POST 后丢失响应的隔离回归。这些验证使用合成实例和本机脚本服务，不连接真实微信，不代表手机实收验收。

提供 macOS ARM64、Linux ARM64/x64、Windows ARM64/x64 CLI，以及 macOS 和 Windows 启动器。macOS 原生程序与隔离升级分别验收；Linux/Windows 交叉构建不能替代目标平台实机验收。macOS GUI 使用 ad-hoc 签名，未经 Apple 公证；Windows GUI 保持交叉构建预览边界。

安装包不包含核心开发源码和第一方 source maps；运行所需 JavaScript、凭据 SDK、框架说明和第三方许可保留。使用 `SHA256SUMS`、`release-manifest.json` 和官方发行签名核对构件身份。本次发布不自动部署或修改任何既有实例。
